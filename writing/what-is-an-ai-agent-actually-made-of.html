What is an AI agent actually made of?

A language model is one part of five. The others decide what it knows, what it can reach, how it does a familiar job, and when it keeps going or stops. Each of the five is a place a design decision lives.

Three terms first

Language model
The part that reads, reasons, and writes. It knows what it was trained on, and nothing about your business.
Retrieval
Looking up your own material before answering, so the answer stands on your documents. Often called RAG.
MCP
Model Context Protocol: a standard plug that connects an AI application to outside tools and data.

The model is the part everyone talks about, and one part of five

Harish Kumar put it in one widely shared post: an agent is more than a language model. The model is the brain, and the other four parts decide what that brain can actually do.

He adds two cautions I’d keep. Not every agent needs all five, and a connection on its own doesn’t make anything an agent.

What an agent knows changes what it builds

Before designing anything for review, I gave a coding agent one request twice: add bulk actions to a customer data table built from a React component system.

One run read twelve written design rules first. The other had only the components, the tokens, and the stories.

Both passed. The difference only shows where the parts run out, which is why what an agent may read is a design decision, not a setup step.

The loop is where the person comes in

The fifth block is the loop: plan a step, use a tool, check the result, and go on. In Agent Review’s simulated run, I hand the agent a job: bring Relay’s billing screens onto the design system, and change nothing anyone can see.

The loop met a cancel link built by hand, quieter than every other action.

Following the rules would have made cancel easier to find, in a job meant to change nothing. So the agent didn’t guess. It stopped on that one change and asked.

I think that stop is the most designed thing in the run. Every block upstream fed it, and the question it raised was mine to answer.

An agent is only as good as the moment it knows to stop.

Check yourself

1For an agent on your team, which of the five blocks has nobody designed?

It’s usually retrieval or the stop. Someone picked the model; nobody decided what it reads or when it hands back.

2What can your agent touch that can’t be undone?

That list is where it should ask first. A connection is a capability, and every capability needs a limit someone chose.

The idea: Harish Kumar, Your AI agent is more than just an LLM. The example: Agent Review, a simulated run, on this site.
