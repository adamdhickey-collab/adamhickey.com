What does a requirements doc need once the product is AI?

Everything a good one already has, plus a plan for judging output that changes every time: the cases it must handle, the ones it must refuse, and the bar it has to clear before launch. The problem still goes on page one. The evaluation plan goes in before anyone writes a prompt.

Three terms first

PRD
Product requirements document: the problem, who it’s for, what success looks like, and what was decided.
Evaluation set
A fixed list of real inputs and the answers you’d accept, run against every change.
Edge and negative cases
Inputs that are unusual, and inputs it should decline. Both belong in the set.

An AI feature gives a different answer every time, so “done” needs a test

A button either submits the form or it doesn’t. A summary, a recommendation, or a drafted reply is different on every run, and some runs will be wrong.

Moe Ali of Product Faculty shared a PRD template he credits to an OpenAI product leader. It runs in four stages and twenty-four sections, and the testing starts in the second stage.

The habits of a good PRD still apply, first

This fall I read the shared templates from Amazon, Linear, Intercom, Figma, and others. The good ones agree: the problem on page one, the metric before the feature, and a log of every call with the options turned down.

Twenty-four sections is a menu, not a form

Some readers called the template waterfall with a new label. I think they’re half right. Filled in at once, it would be.

The best documents I read grow a little at each review, and the detail matches the risk. A two-day fix gets a paragraph; a feature that answers customers gets the evaluation plan in full.

The one section I’d never cut is the evaluation plan, because it’s where “good enough to ship” gets written down before anyone is invested in the answer.

Write the test for the answer before you write the prompt.

Check yourself

1For your AI feature, what is one input it should refuse?

If nobody can name one, the evaluation set has no negative cases yet, and the feature will meet its first one in production.

2Was the bar for launch written before or after the first demo?

A bar set after a good demo tends to fit the demo. Set it while nobody has seen an answer yet.

The idea: an AI PRD template shared by Moe Ali, Product Faculty. The example: the shared PRD templates I read this fall, from Amazon, Linear, Intercom, and Figma.
