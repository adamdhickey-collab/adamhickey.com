What is a product designer for, when anyone can build?

Understanding why something matters, making it real fast enough to find out, and knowing when it isn’t good enough. AI collapsed the distance between an idea and working software. Understanding people still takes as long as it did.

In this article

  1. The handoff is disappearing, and the walls between roles with it
  2. A working prototype is a question, not an answer
  3. Building fast doesn’t make understanding fast
  4. A prototype should leave something the team can build from
  5. Knowing enough engineering isn’t owning all of it

Key idea 1 of 5

The handoff is disappearing, and the walls between roles with it

A few years ago, an idea of mine went through a sketch, a wireframe, a prototype, a review and a handoff to an engineer. Weeks, if it went well.

Now I describe it to a coding agent, and the first version runs in a browser the same afternoon. So what am I now: a designer, an engineer, a product manager?

I started in 2005 as a hybrid designer and developer, went with design when the roles split, and build what I design again now.

The wall between roles was never where a designer’s value came from. It came from understanding a situation well enough to make better decisions, and that part didn’t get cheap.

Key idea 2 of 5

A working prototype is a question, not an answer

When a working version costs an afternoon, it’s tempting to treat it as the answer. I think it’s a question, and the fastest way to ask it is to let people use the thing.

Better generation wouldn’t have fixed that. A different system did. So each prototype should end in a call, build, kill or park, as in What should a working prototype actually prove?

A fast prototype is worth the assumption it breaks.

Key idea 3 of 5

Building fast doesn’t make understanding fast

A misunderstood requirement can now become a working feature before anyone notices. And some knowledge can’t be generated at all.

Each place in Door County Found, the guide I built and my sister keeps current, opens on a line about why we love it, from decades of visits. AI wrote the code. It couldn’t have written the guide.

Looking hard doesn’t settle it either. I approved a black bear for Faunaform, my print studio, with five legs. A dark shape under its rump read as a fifth, and I didn’t see it. It was caught the next day.

You can make building much faster without making understanding any faster.

The wall between roles was never where a designer’s value came from.

Key idea 4 of 5

A prototype should leave something the team can build from

A throwaway prototype answers its question and disappears, and the next team starts from nothing.

Door County Found is my small version. Every place is structured data, so the filters are real, and my sister keeps it current through a web form without touching the code.

It also has an honest exit. Everything is structured markdown, so moving it is mechanical, not a rewrite.

A prototype that only answered its question has done half its job.

Key idea 5 of 5

Knowing enough engineering isn’t owning all of it

There’s a bad reading of all this: if a designer can build, one person can do the work of a team. I don’t believe it.

Security, infrastructure, scale, on-call and years of maintenance are disciplines of their own, and a working prototype touches none of them.

Part of the skill is knowing where your end is. Door County Found is a static site that costs about $12 a year, chosen so there would be nothing to maintain.

The first editing tool I tried needed a server runtime I couldn’t promise to keep running, so it went.

Knowing enough engineering to test an idea is different from owning the system it runs in.

In one breath

Coding agents closed the distance between an idea and working software. A designer is for the hard part that’s left: why it matters, finding out fast, and knowing when it isn’t good enough.

If you do one thing: before you build the next version of anything, write down the question it has to answer. Then name the person who will answer it by using it. If you can’t name both, go talk to someone first.
